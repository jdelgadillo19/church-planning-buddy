In Grapevine, I'm thinking about how everything should be structured for use. I'm getting to the point where I'll be setting this up for my church's workflow and I want to outline the info structure before actually committing everything.

Mainly, I want the end user to provide a ready-made slideshow file that is uploaded for use on the presentation rig. I want people to be able to pull only the needed files for each week form a central database, and I want for a pull to not require human action on the part of the database. Let me define a few things

-----
DB Hosting/usage
-----
GDrive
- Holds the working copy of the DB as a Shared Drive
- Grapevine sends JSON build instructions to web-hosted database and interprets which files need to be downloaded for use by the user

Presentation rig
- holds a backup copy of the database. Can be configured to updated periodically.

-----
Devices
-----

Presentation rig
- pulls finished slideshows on the service day for use
- Holds a local backup copy of the full database, zipped and uploaded periodically

Remote device
- Used as a workstation by Admins and Users for editing PP presentations and possibly db/auth management depending on auth

-----
Auth
-----
Owner/Org (i.e. info@church.org or hello@church.org)
- A church or org that has highest level permission to make auth changes and database edits.
- At least one account must be listed, and only the Owner/Org account can make changes to who is/isn't owner. Can only self-remove from Owner status
- Can configure DB paths for use by Grapevine

Admin (i.e. pastor@ or worshipdirector@ or techdirector@)
- Default to full auth controls over file and tool access
- Has full edit control over db editing and over user permissions

User (i.e. volunteer@)
- is given access to specific tools for use, and has limited database editing authority. 
- Can call copies of files to remote device for working, and upload finished or working copies of the presentation to be made available for pulling by other users/for the presentation rig.

-----
Sample workflow
-----

1. PrezInit
    no playlist/presentation exists for a given week
        - JSON prez build instructions are generated by Grapevine and used to select files needed for an initial presentation build pull from GDrive. 
        - All files are downloaded onto remote device, and assembled into an initial slideshow using the remote device's ProPresenter client
        - User manually edits slideshow to match planning requirements
        - Once the work is done, user uses Grapevine to upload the finished or working presentation to GDrive

2. PrezEdit
    A working copy of the presentation exists for a given week and is uploaded to the GDrive
        - User can download a copy of the working presentation (along with all its associated files) for additional editing, or simply to check accuracy
        - User can edit as needed using the locan ProPresenter client.
        - once done, User can use Grapevine to re-upload the edited presentation to GDrive for later use
            - both the old copy and the new copy are maintained for safety, QA, and failure tracking

3. Gameday
    Presentation rig is being prepared for event
        - PrezUser uses Grapevine client to check for existing presentation on GDrive
        - PrezUser pulls the presentation onto local device
        - if Library files conflict, user can decide whether to use existing local file or edited pulled file
        - Presentation is then used during normal working flow.
    If no slideshow is prepped
        - PrezUser can use Grapevine to quickly generate a presentation for use
    If Grapevine fails
        - PrezUser can use the local db for emergency manual prez building
