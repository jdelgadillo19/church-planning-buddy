## Round 1 — Agents

### John (Product Manager)

**JTBD:** Sunday-morning certainty — open ProPresenter and the deck matches plan + what leaders approved, without rebuilding slides by hand.

**In v1:** PCO + existing GRG pipeline; one plan → one presentation; signoff before write; narrow “good enough complete” for your typical Sunday; log skips/conflicts.

**Out of v1:** Ableton SOT, full conflict UI, SMS bot, gdrive-organizer as runtime dependency, pixel-perfect every PCO edge case.

**Prove value with four falsifiable claims:** time saved vs native import + cleanup; trust after one rehearsal; defined completeness %; repeatability on a second plan same month.

**Phased roadmap:**

1. Definition (JTBD, complete checklist, dumb conflict rule, PP integration path, golden plan ID)
2. Read-only merger → ProPresenter-oriented manifest + review (no PP write)
3. Write + one golden worship template; measure vs baseline
4. Hardening (overrides, yellow-tier gaps, second plan type)
5. SOT engine only after a real user quote from phase 2

**Pushback:** “Not another importer” is positioning; users still compare to import. Beat import on **cleanup time and trust**. ProPresenter writes need **stricter** preview than GRG.

**Gating question:** After rehearsal, what does the tech director say they *didn’t* have to do — in under ten words?

### Winston (System Architect)

**North star:** Inputs = PCO plan + GRG-derived content. Output = ProPresenter deck that is **rehearsal-acceptable**: order, cues, text, media linked or **flagged** — not cinematic polish.

**Reuse from GRG MVP:** PCO fetch, Drive/GRG resolution, preview + diff + signoff, apply orchestration, audit trail. Mentally rename to **Service Assembly Pipeline** with pluggable sinks (Google Doc today, ProPresenter tomorrow).

**New core pieces:**

1. **Service Asset Model** — canonical intermediate (`ServicePlan`, `ServiceItem`, `ContentBlock`, `MediaRef`, `ArrangementHint`); don’t map PCO → cues directly.
2. **Entity resolution** — PCO song ↔ PP library; GRG section ↔ items; confidence + overrides.
3. **ProPresenter adapter (local)** — Remote API vs file/bundle; hybrid default.
4. **Presentation builder** + **completion checker** (missing media, order mismatch, empty slides).

**Split architecture:** Cloud app assembles + previews; **local agent** applies to ProPresenter on LAN (manifest + text, not 4GB media).

**SOT boundaries (MVP):** Order = PCO; spoken copy = GRG; slide media = ProPresenter library (resolve into it).

**“Completed” checklist:** structure matches PCO; text on non-song items; songs linked or UNRESOLVED; metadata (date, plan id, build id); human approve; optional playlist if API reliable.

**Sequencing:** Service Asset export → local dry-run stub → PP adapter (text + order) → library resolver → completion checker + signoff UX.

**First PR:** S1 + PROP-0 + tests. Second PR: writer + AC-PROP-2 (opens in PP7). Third: agent wiring.

### Mary (Business Analyst)

**Reframe:** From GRG utility → first wedge of **production coordination layer** — predictable, repeatable, approvable handoff from plan + GRG to review-ready ProPresenter.

**Hypothesis:** Churches trust agent-assisted pipeline if **quality + traceability** beat native import + manual cleanup.

**Scope guardrails:** No importer parity race, no Ableton/Drive in pilot, no “fully autonomous” story, no gdrive-organizer in MVP unless blocking.

**“Completed” ladder:** MVP = order + titles + media hooks + exception list; not typography perfection or unattended sanctuary publish.

**Pilot metrics (1 church):** time-to-rehearsal-ready; exception rate trending down over 3–4 services; used live without workflow revert + “would run again” score.

**Recommend:** Re-anchor repo/epic as **Service deck assembly agent** — inputs PCO + GRG, output ProPresenter, gate human approval.

## ProPresenter 21.3 API constraints (post-questionnaire)

| Capability | Verified |
|------------|----------|
| Playlist create | Yes |
| Arrangement tile reorder | **No** (no documented API) |
| Library enumerate/query | Yes |
| Native full-text search | **No** — CPB builds local index |

**Revised MVP “complete”:** New presentation + full playlist (order, songs, template cues present). Arrangement fidelity = **best-match selection** + **NEEDS_ARRANGEMENT** flag; manual tile work in ProPresenter when GRG ≠ any indexed arrangement.

**Architecture:** ProPresenter = content source + playlist sink; CPB = search + organization intelligence + signoff.
