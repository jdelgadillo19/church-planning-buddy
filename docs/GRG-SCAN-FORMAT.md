# GRG scan section format

Reference: [`downloads/Get Ready Guide (SUN).docx`](../downloads/Get%20Ready%20Guide%20(SUN).docx) and [`PRODUCT.md`](../PRODUCT.md) §1.7.

## Regions per song scan

| Region | Layout | Content |
|--------|--------|---------|
| **Header** | Single column | Bold song title, metadata (By, ©, CCLI, bar counts), ending in a full-width divider rule |
| **Lyrics** | Two columns | Verse/chorus labels, lyrics body, interlude markers |

The full-width divider between header and lyrics is generated by the engine (a bottom-bordered paragraph), not copied from the source scan, so it spans the page consistently.

## Styling source of truth

Scan styling **and column layout** are **template-driven**, not copied from the org scan. The template's `{{STYLE_*}}` exemplars (see [`GRG-TEMPLATE.md`](./GRG-TEMPLATE.md) → *Scan style exemplars*) define the look; the engine captures those run styles **and the column layout of the section each exemplar sits in** (`captureScanStyleSpec` in [`src/lib/docs/scan-style-template.ts`](../src/lib/docs/scan-style-template.ts)), classifies each source line, and inserts **plaintext** styled to match. The source scan's own fonts/colors are discarded. The header/lyrics column split (single vs two columns) is whatever the template's exemplar sections define — change the columns of an exemplar's section in the Google Doc and the next run follows it.

## Import heuristics (`src/lib/docs/scan-import.ts`)

1. **Header / lyrics split** — lyrics begin at the first of:
   - A horizontal rule / divider line (dashes `――――` **or** underscores `________`)
   - A line starting with `VERSE`, `CHORUS`, `BRIDGE`, `PRE-CHORUS`, `INTRO`, `TAG`, `OUTRO`, or `CODA`
   - After a CCLI line, the next bar-count or verse line
   The source's separator text is dropped; the engine renders its own full-width divider (see Layout).
2. **Fallback** — if no marker found, first ~4 paragraphs treated as header.
3. **Line classification** (picks the `{{STYLE_*}}` token):
   - header line 0 → `title`; remaining non-rule header lines → `credit` (the title is never duplicated into credits)
   - `^\d+\s*Bar\s` → `bar`; `VERSE/CHORUS/BRIDGE/PRE-CHORUS/INTRO/TAG/OUTRO/CODA` → `label`; else `lyric`
   - a trailing `END` line is appended (lyric style) to match the golden
4. **Layout** (derived from the template, not hardcoded) — staged, index-robust:
   - Per song, one batch appends (all via `endOfSegmentLocation`, so no indices are predicted): a leading section break (`NEXT_PAGE` for the per-song page break, else `CONTINUOUS`) → header text (title + credits) ending in an empty **divider** paragraph → a `CONTINUOUS` section break → lyrics text + `END`.
   - A second batch re-reads the real paragraph/section indices and applies: per-line `updateTextStyle` from the template spec, a full-width solid `borderBottom` on the divider paragraph (it lives in the single-column header section, so it spans the page), and one `updateSectionStyle` per section using the captured `columnProperties` — header single column (`spec.title.columns`), lyrics two columns (`spec.bar.columns`).
   - Because the header section and the lyrics section are explicit, columns never cycle inside the lyrics block, and the two-column lyrics never bleed into the next song's header (each song's `NEXT_PAGE` break resets to single column on a fresh page).
   - This replaced an earlier version that hand-computed indices across interleaved section breaks and 400d (silently falling back to plain mode for every song).
5. **Import modes** (per song, in order):
   - `styled` — plaintext insert with per-line styles + template column layout
   - `plain` — fallback `exportDocPlainText` + single-column append (warning shown; e.g. source is not a Google Doc)

## Manual format notes (fill in as needed)

- Header ends at: the divider line after the CCLI block (dashes or underscores); the engine re-renders it as a full-width bottom border.
- Two-column boundary: a `CONTINUOUS` section break after the divider (single-column header → two-column lyrics). Column counts and widths come from the template exemplar sections, not constants in code.
- Styling: applied per line from the template `{{STYLE_*}}` exemplars (size, family, bold/italic, color, highlight). Org-scan run styles are **not** copied.
- Red bar markers and yellow section-label highlight come from `{{STYLE_BAR}}` / `{{STYLE_LABEL}}`, so they stay consistent regardless of how the source scan was styled.

## Song list formatting (intro)

`buildSongListLines` ([`src/lib/docs/grg-mutate.ts`](../src/lib/docs/grg-mutate.ts)) emits `Key of {key}: {title} - {artist}` (space after the colon). The artist is the PCO arrangement name; a leading short arrangement code (e.g. `XX - `) is stripped via `stripArrangementPrefix` so only the band/author remains.
